# *Accesibilidad*: incorporada y medida

El objetivo es **WCAG 2.2 nivel AA** en cada superficie. La mayor parte está decidida en los tokens, y medida.

## Contraste

Calculado desde los valores reales de los tokens: `bun run tokens:check` falla si una combinación de la que depende el producto baja de su mínimo. El texto necesita **4.5:1** (7:1 es AAA); las partes de interfaz como bordes de campo y anillos de foco necesitan **3:1**. Las últimas filas son combinaciones del propio sistema que se quedan cortas. Ningún componente las usa.

## Dónde se queda corto el sistema, y qué hacemos

| La combinación del sistema | Ratio | Qué hace el producto |
| --- | --- | --- |
| Crema sobre clay-500: el botón y la tarjeta arcilla | 3.8:1 | El botón se rellena con **clay-600** (5.2:1). El texto de una tarjeta arcilla es de **24 px o más**, o la tarjeta usa el tinte clay-200 |
| Clay-600 sobre clay-200: el chip arcilla | 4.1:1 | El texto del chip es **clay-700** (5.3:1) |
| Clay-500 como texto sobre crema | 3.5:1 | La arcilla es un relleno, una regla, un anillo y un borde de error. El **texto** de error es clay-600 (5.2:1) |
| Lime-600 como texto sobre crema: el eyebrow lima | 1.4:1 | El eyebrow lima solo aparece sobre un campo carbón, donde lime-500 es 11.6:1 |
| La línea fina crema como borde de campo | 1.5:1 | Los campos usan `--field-border`, charcoal-500 (6.1:1). Las tarjetas y las reglas conservan la línea fina |
| Línea fina charcoal-500 como borde de campo sobre oscuro | 2.3:1 | Los campos oscuros usan charcoal-400 (4.7:1) |

Nada de esto cambia el aspecto del sistema: mueve un color de texto o un relleno un paso.

## Foco

Toda parte interactiva muestra un indicador de foco visible: un **contorno arcilla de 2 px, a 2 px de distancia**. La arcilla es 3.5:1 sobre crema y 3.8:1 sobre carbón, suficiente para una parte de interfaz. Nunca quites el contorno sin reemplazarlo. El orden del foco sigue el orden de lectura, y un diálogo atrapa el foco, lo devuelve y se cierra con Escape.

## Teclado

| Componente | Teclas |
| --- | --- |
| Botón, chip, enlace | Enter, Espacio |
| Tabs | Las flechas mueven, Inicio y Fin saltan |
| Menú | Las flechas mueven, Enter elige, Escape cierra |
| Diálogo | Tab cicla dentro, Escape cierra |
| Interruptor, checkbox | Espacio |
| Grupo de radios | Las flechas mueven y seleccionan |

## Tamaño del objetivo

**44 por 44 px** en superficies táctiles (el Hub, la encuesta, mobile). **24 por 24 px como mínimo** en escritorio (WCAG 2.5.8), con separación para que los vecinos no se solapen. Los visuales pequeños tienen un área de pulsación mayor.

## El significado nunca va solo en el color

Un estado lleva una **palabra, un relleno, una regla izquierda de 3 px y una marca**. Una tendencia lleva una **flecha y un signo**. Un gráfico tiene **etiquetas o anotación directa**, y una alternativa de texto que lista sus valores. Los estados seleccionado y actual también cambian de forma o de relleno (un chip relleno, un borde lima, `aria-current`).

## Movimiento

Las duraciones son tokens. Con `prefers-reduced-motion: reduce` pasan a `0ms`, el desplazamiento al pulsar pasa a `0`, el brillo del skeleton se detiene y nada entra moviéndose. Nunca hay destellos por encima de tres veces por segundo.

## Formularios

Una **etiqueta visible** en cada control, nunca solo un placeholder. El **texto de error** se liga con `aria-describedby`, se anuncia con `role="alert"` y se escribe como una solución. Obligatorio es lo normal; lo opcional se marca. Usa el `type`, el `inputmode` y el `autocomplete` correctos.

## Contenido

- Minúscula de oración, palabras sencillas, una idea por frase.
- El texto de un enlace tiene sentido solo ("Leer el caso", no "Haz clic aquí").
- Las imágenes que llevan significado tienen texto alternativo; las decorativas llevan `alt=""`.
- Los números conservan unidades y contexto: "4.6 de 5", no "4.6".

## Revisar un componente

1. Llega a él con Tab y úsalo solo con el teclado.
2. Amplía al 200% y a un ancho de 320 px: nada se pierde ni se solapa.
3. Activa el movimiento reducido: nada se mueve.
4. Léelo con un lector de pantalla: nombre, rol, estado y valor se pronuncian.
5. Míralo en escala de grises: cada estado sigue claro.
6. Si añades una combinación de color, añádela a la lista de guarda de <code>scripts/build-tokens.ts</code>.
