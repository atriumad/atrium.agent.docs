# *Componentes*: las piezas que comparten todas las superficies

Estos son los componentes que el producto necesita, en el orden en que se construyen. Cada página muestra el componente en vivo, en sus estados, con su anatomía, su API y sus reglas. El código de estas páginas es el que adopta `packages/ui`.

## El contrato

Todo componente cumple las mismas reglas. Un componente que no puede no está terminado.

1. **Lee roles, no colores.** Solo los tokens de [Colores](./colors), para que una superficie lo pueda retematizar.
2. **Tiene todos los estados.** Reposo, hover, foco, activo, deshabilitado y, donde aplique, cargando, error y seleccionado.
3. **Se usa completo con teclado.** Alcanzable con Tab, operable con Enter y Espacio (y flechas en tabs y menús), con el anillo de foco de [Fundamentos](./foundations#foco).
4. **Tiene nombre para la tecnología de apoyo.** Una etiqueta visible, o un `aria-label` en las partes solo de icono. Los errores se anuncian (`role="alert"`) y se ligan al campo.
5. **Nunca depende solo del color.** El estado lleva una palabra y una marca.
6. **Respeta el movimiento reducido.** Las duraciones son tokens que bajan a cero.
7. **Los objetivos son suficientemente grandes.** 44 px en móvil, 24 px como mínimo en escritorio.
8. **Tiene un diseño de carga, de vacío y de error** donde sea que contenga datos.
